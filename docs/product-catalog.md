## 3. Catalog Extension Architecture

As PortfolioStore 99 expands its template collection, new products are registered following this standard schema:

```json
{
  "id": "store-[slug]",
  "slug": "store-[slug]",
  "name": "Template Name",
  "category": "Newbie | General | Premium",
  "price": 99 | 199 | 399,
  "priceUsd": 1.99 | 3.99 | 7.99,
  "currency": "INR",
  "tagline": "Brief 1-sentence value hook.",
  "description": "Full description of features, tech stack, and use cases.",
  "thumbnail": "/templates/store-[slug]-preview.png",
  "previewImage": "/templates/store-[slug]-preview.png",
  "previewUrl": "https://store-[slug].vercel.app",
  "liveUrl": "https://store-[slug].vercel.app",
  "tech": ["Framework", "Library", "Styling"],
  "features": ["Feature 1", "Feature 2", "Feature 3"],
  "includedFiles": ["Deliverable 1", "Deliverable 2", "Deliverable 3"]
}
```

Every new template addition requires:
1. A deployed, working Vercel preview URL (`https://store-[slug].vercel.app`).
2. An unbundled, verified source archive registered in the fulfillment mechanism (`lib/drive.js`).
3. An accurate preview screenshot (`/public/templates/store-[slug]-preview.png`).
